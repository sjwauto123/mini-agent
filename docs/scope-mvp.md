## 方案 A：精简交付，已确认

### 保留

1. Python + FastAPI、React + TypeScript + Vite，本机单用户无登录。界面仅会话列表、聊天、模型选择、停止和工具执行记录，不建设管理后台。
2. 自研单进程 Runtime，顺序执行工具，包含最大轮次、超时、协议解析、参数校验、同会话忙碌保护与有限模型重试。
3. SQLite + SQLAlchemy 异步访问 + Alembic。会话、消息、摘要、待办及执行结果持久化，重启后能继续聊天。
4. 六个工具保持不变：calculator、todo、mock search、mock weather、resource_read、resource_search。外置能力保留以处理此前重点讨论的大结果和超长输入，但不建设通用文件平台。
5. 外置首版只处理纯文本和 JSON 数据，元数据入库、正文存本地持久化目录；单份默认 10 MiB，跟随会话保留。PDF/Office/OCR、向量检索、大型索引系统不纳入首版。具体范围定位与查找规则在精简设计集中确认。
6. 上下文保留系统规则、会话摘要、近期完整回合和本轮调用链。沿用软 70%、硬 85%、目标 55%，每次请求最多 2 次摘要尝试，原历史不删除，失败有条件降级。
7. 保留关键工具状态、对象 ID 与任务事实的结构化记录；用户对话事实由基础会话摘要保存，不额外建设独立的用户记忆管理系统或模型自动长期记忆写入流程。
8. 沿用按模型窗口和操作比例决定的外置/读取预算，不恢复固定 token 截断。默认概览 1%、正文读取 10%、查找 2%、外置阈值 10%。
9. 具名模型配置由配置文件定义、密钥使用环境变量引用，页面只选择已有配置；httpx 接入一个实际联调服务，原生工具与 JSON 两种解析复用相同 Runtime。运行固定配置，摘要用同模型，有限重试。
10. 保留 run_id 与服务进程内后台运行、SSE 阶段进度、协作式停止。浏览器断连不取消；重开页面读取持久化运行状态和结果。
11. 自动化测试覆盖原始 23 个验收场景中保留的要求，并按精简范围调整实现相关断言；补充外置读取、预算和本机 Web 工作流测试。真实模型验证独立报告，不以 Fake LLM 代替真实接入验收。

### 延后或简化

- PostgreSQL 接入、双数据库集成验证及生产部署延后；首版只声称已验证 SQLite。保留便于迁移的数据访问边界，不声称已经支持未测试的数据库。
- 可插拔执行器先用一个清晰的运行入口，不建立 Worker、分布式任务或复杂执行者仲裁体系。
- 服务崩溃后将未完成运行标记中断、保留已知结果。用户通过正常对话继续，首版不提供检查点恢复或专用“继续旧运行”按钮。未知副作用不自动重做。
- SSE 先推送阶段事件与完整答案，模型逐字流式展示延后；页面重连读取状态快照和既有结果，不实现持久化事件补发系统。
- 暂不建设通用人工审批引擎。首版只提供上述已限定工具，执行用户授权的查询及本地待办操作；没有对外发送、支付、不可逆删除工具。未来引入这些能力时再按 D31 增加具体审批流程。
- 不建设模型配置编辑后台、自动路由、自动备用模型、账户配额平台、监控仪表盘或多租户认证。基础输入限制、资源大小检查、会话归属、错误和执行日志仍须实现。

这些已生效调整涉及 D02、D04、D24、D27、D28、D31、D35 的首版范围，以及 D05 结构化记忆实现的简化。没有取消原始工具注册、LLM 自主选择、会话隔离、追问或压缩要求。
