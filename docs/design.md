# Mini Agent 精简详细设计

版本：v4。范围 A 与 I1-I4 已确认，设计阶段完成，进入实现。尚无应用代码。

依据：[原始需求](requirements.md)、[精简范围](scope-mvp.md)、[决策历史](decisions.md)。本文件替代 v1/v2，历史选型与当前范围冲突时以精简范围为准。

## 1. 已确认范围

- Python + FastAPI，React + TypeScript + Vite，本机单用户无登录。
- 自研 Loop、工具注册、模型解析、会话和上下文管理，不依赖 Agent 框架。
- SQLite + SQLAlchemy 2 异步访问 + Alembic；首版只验证 SQLite，PostgreSQL 延后。
- 六工具：calculator、todo、mock search、mock weather、resource_read、resource_search。
- 会话、历史、摘要、待办和资源严格隔离，重启后可继续聊天。
- 配置文件定义具名模型，密钥使用环境变量引用；会话选择配置，httpx 接入实际联调端点；原生工具与 JSON 两种模式共用 Runtime。
- 单进程后台 run，与浏览器连接分离；同会话忙碌拒绝新任务，支持协作式停止。
- SSE 提供阶段事件及完整回复；重连读取状态快照，不做逐字输出和事件补发。
- 上下文软阈值 70%、硬阈值 85%、目标 55%；每个用户请求最多 2 次实际摘要调用。
- 大结果和超长输入外置，数据库存元数据、本地目录存正文；单份默认 10 MiB，随会话保留。
- 按有效输入预算计算外置阈值 10%、概览 1%、正文读取 10%、查找 2%，实际返回受剩余空间限制。

首版不实现 Worker、登录系统、通用审批、独立长期记忆平台、PDF/Office、向量检索、检查点续跑、生产部署和管理后台。六个工具不包含外部发送、支付或不可逆删除。

```text

  runtime.py      # 循环、预算、停止、忙碌保护
```

文件过大后再拆分，不提前建立插件体系。Runtime 依赖注册表，不通过用户输入关键词分发业务工具。

## 3. Loop 与模型协议

### 3.1 执行顺序

1. 后端使用固定本地身份校验会话，检查输入和模型配置，原子取得该会话执行权。
2. 保存 user 消息与 run，返回 run_id；服务内任务继续，浏览器断开不取消。
3. 组装上下文，按需外置/压缩，提供工具名称、描述和参数 Schema。
4. 调用模型并解析 Final、ToolCall 或 Invalid。
5. Final 保存答案并结束；ToolCall 校验并执行，结果进入上下文后继续；Invalid 有限纠错，无法修复则受控退出。
6. 停止、预算耗尽或错误均记录真实进度，安全结束后释放会话执行权。

候选状态：running、cancel_requested、completed、failed、cancelled、limit_reached、interrupted。cancel_requested 不是终态，不立即放开会话忙碌保护。

每个数据目录只允许一个后端实例；启动确认独占后，将遗留运行标记中断并保留已知结果。用户正常发送新消息继续，不自动重放旧请求。

### 3.2 解析契约

原生模式：读取结构化工具调用 ID、名称和参数，正文作为可选 decision_summary；无工具调用时，非空正文作为最终答案。

JSON 模式候选格式：

```json
{
  "action": "tool_call",
  "decision_summary": "先查询天气",
  "tool": {"name": "weather", "arguments": {"city": "北京", "date": "2026-09-13"}},
  "answer": null
}
```

最终回复为 action=final、tool=null、非空 answer；Runtime 为 JSON 调用生成唯一 call_id。不依赖隐藏推理，缺失摘要不伪造。

每个响应最多一个工具调用，参数完整校验后执行。拒绝畸形/截断输出、重复 JSON 键、非有限数、未知工具及多调用；不从自由文本猜工具指令。

信封完整而参数错误时保存匹配的 assistant/tool 错误对；结构损坏的输出只留 trace，用临时纠错提示修复，不生成悬空历史。模型重用已出现的 call_id 视为协议错误，不重复追加消息。

配置包含 endpoint、model、api_key_env、mode、context_window、output_reserve、tokenizer。运行固定配置和预算，摘要同模型；服务端实际输出上限与 output_reserve 对齐，缺少能力信息不能静默猜测。

## 4. 工具候选接口

注册项包括 name、description、JSON Schema、handler、只读/本地写类别。Schema 拒绝未知参数；user_id/session_id 由 Runtime 注入，模型不能指定其他作用域。

- calculator(expression)：AST 白名单四则运算、括号和正负号，禁止 eval、函数和属性访问，检查复杂度、除零与非有限结果。
- search(query)：固定 mock 语料，返回标题、片段、来源和 mock=true，无命中为空列表。
- weather(city,date)：返回模拟城市天气与绝对日期，mock=true；不支持的城市/日期明确报错。
- todo(action,text?,todo_id?)：add、list、complete，仅操作本会话；没有删除动作，重复完成已完成项仍成功。
- resource_read(resource_id,cursor?,limit?)：范围读取，返回实际位置、next_cursor 和结束标志；请求量还受 token 预算限制。
- resource_search(resource_id,query,cursor?)：返回有界匹配片段、位置和继续查找游标。

统一结果包含 ok、data、error、mock、truncated；错误包含 code、message、outcome(not_executed/failed/unknown)，可另带 detail。detail 只在工具结果里回给模型（用于指明哪个字段不合法、便于自我修正），前端不渲染 tool 消息，因此不会把内部报错暴露给用户。无搜索结果是成功业务结果。

todo 写入、调用终态和 tool 结果消息同事务提交。幂等键为 run_id + call_id，同键同参数返回既有结果，不重复写；同键不同参数报冲突。工具注册表不含根据用户措辞猜测路由的分支。

当前六工具执行已授权查询和明确请求的本地待办操作。未来新增外部写工具时再引入已讨论的确认流程，不为不存在的工具建设通用审批引擎。

## 5. 上下文与资源

### 5.1 组成与预算

顺序：系统规则、可信日期/时区、标明为资料的摘要、近期完整回合、当前输入与本轮工具链。工具 Schema 同样计入预算。

保留目标、事实、约束、未完成事项与关键工具 ID/结果；不放密钥、长堆栈、完整 trace 和冗长决策说明。外部工具数据不能覆盖系统规则。

结构化状态仅保存实际工具事实与对象引用，用户事实由基础摘要保存，不单建用户画像。近期优先保留最多 4 个完整回合，可按预算减少。

B = 模型窗口 - 输出预留 - 协议开销 - 安全余量。tokenizer 匹配时使用 tokenizer，否则保守估算并标记；各字段计数一次。估算不能保证所有供应商绝不拒绝，服务端拒绝应明确报告。

### 5.2 压缩流程

1. 每次模型调用前检查；低于 70% 时不新增摘要。
2. 达到软阈值，摘要较早完整回合，目标 55%；摘要有版本和覆盖截止 seq，成功后才替换旧摘要。
3. 达到 85% 或软压缩后仍超硬阈值，进一步精简摘要、减少近期原文和缩减工具结果；有额度时可追加一次更强摘要。
4. 每次用户请求最多 2 次实际摘要请求，包含失败/重试；工具返回后不重置。无新内容或新策略不重复相同请求。
5. 目标不是失败界限。无法达到 55% 但有有效输入可继续；失败回退到有效摘要和有界完整回合，并标记省略，不能伪称摘要覆盖了被丢弃部分。
6. 当前必需输入经过支持的缩减/外置仍无法容纳，才返回 context_too_large。

摘要输入本身必须在容量内；历史过多则只处理能容纳的连续完整回合，未处理历史继续保存在数据库。不能截断 JSON 或拆开工具调用/结果。缺少关键任务依据时澄清，不编造记忆。

### 5.3 外置保存与读取

普通结果超过 B 的 10% 或当前剩余空间不足时外置；概览最多 1%，读取 10%，查找 2%，包含完整包装且受请求范围与剩余空间限制。空间不足先压缩再重新计算，不将读取缩减到无法推进。

读取响应直接分页，不再次外置。游标必须对应实际返回位置，长记录未读尾部可以继续读取。

超长输入保存为会话文档，提供引用。界面允许长资料附短任务说明；任务意图不明确时澄清，不能假装读取局部就完成全文审阅。

接收/生成过程中检查 10 MiB 上限；文件先写受限临时内容，完成后原子更名，再提交元数据，失败做清理。只暴露元数据已提交的资源；失效引用报错。不能因文件失败将已完成待办误报成未执行。

## 6. 存储与 Web 接口

最小表：sessions、runs、messages、tool_calls、summaries、todos、resources、trace_events。消息有会话内递增 seq，摘要记录版本和覆盖点；run 记录状态、模型快照、请求幂等键、计数和结果。resource 记录归属、类型、大小、内部文件键与来源。

读取与写入均校验固定本地身份和 session_id；客户端不能通过 resource_id/todo_id 绕过会话隔离，不能提交任意文件路径。

候选 API：

```text
GET    /api/models                       不含密钥的模型列表
POST   /api/sessions                     新建
GET    /api/sessions                     列表
PATCH  /api/sessions/{id}                空闲时更换模型
GET    /api/sessions/{id}/messages       历史
POST   /api/sessions/{id}/runs           提交，返回 202/run_id
GET    /api/runs/{id}                    状态与结果快照
POST   /api/runs/{id}/cancel             协作式停止
GET    /api/runs/{id}/events             SSE
GET    /api/runs/{id}/trace              执行记录
POST   /api/sessions/{id}/resources      受限资料导入
```

客户端生成 request_key，同键同输入返回原 run，不重复写消息；同键不同输入报冲突。独立第二条消息在会话忙碌时返回 409/session_busy，前端保留草稿。

SSE 先建立订阅再读取/发送当前快照，然后推送新事件，避免快照与订阅之间丢更新；前端按状态更新而非重复追加聊天消息。重连重新订阅和读取快照，不补发旧事件。事件有三类：`snapshot`（运行状态快照，终态做一次权威推送）、`message`（按 `seq` 定位的助手消息增量；一轮确定为工具调用时**随增量下发 `tool_calls`**，前端据此立刻改显示为"调用了 N 个工具"，而不是继续把决策说明当回答渲染）、`notice`（过程性提示，如上游挂起后的"正在重试"——运行状态没有变化，快照推不出内容，没有它那段沉默看起来就是卡死）。

前端仅会话列表、聊天、模型选择、输入/资料、停止、可展开 trace。每个请求携带对应 session_id，不共享一个会污染其他窗口的全局当前会话。

## 7. 错误与中断

- 错误码只有一处来源（`errors` 模块）：异常→错误码的归一化与用户可读文案都从那里取，运行时、接口层、前端不再各写一套字符串判断，避免同一个失败在不同层得出不同的码。错误码集合只增不改，未收录的标识退回异常类名而不是硬塞进码里。
- 模型侧把失败分为可重试与不可重试两类：429/5xx 与传输层故障由运行时有限重试；401/403 记为 model_auth_failed，其余 4xx 记为 model_request_invalid，响应非 JSON 或结构缺失记为 model_protocol_error，都在 trace 里留 model.failed 后再上报。
- 会话忙碌时删除会话整体拒绝，不留任何副作用：忙碌判定与全部数据行的删除在同一事务内完成，资源文件在事务提交后才清理。磁盘清理按"尽力而为"处理：删不掉（占用、权限、平台删除防护）只记日志，不影响删除结果——数据行已经删掉并提交，此时报失败会让客户端误以为删除没生效而反复重试。
- 模型暂时故障最多追加 2 次请求，受 run 总预算限制；认证/参数/容量配置错误不盲目重试。摘要子上限仍为 2 次。等待重试的退避期间会推一条 `notice` 提示，否则上游挂起（实测有 20 秒才断开的情况）时界面毫无反馈。
- 语言约束写成紧贴模型输入的最后一条系统消息：只放在开头 SYSTEM_PROMPT 或协议提示句尾时，实测各轮仍会整轮返回英文推理（会原样显示在思考面板里）。位置比措辞有效，但它仍是模型侧的概率行为，实测 5 轮里约 1 轮会回落成英文。
- 工具参数错误不进入 handler；业务错误反馈模型继续判断。协议纠错有限次，持续错误终止。
- 停止后不启动新步骤；当前可取消等待尽快取消，不承诺远端停止计算或计费。todo 事务提交/回滚后确认结果再结束。
- 停流式输出到一半才失败的运行必须先撤回那条半截助手消息，再由统一的收尾提示交代结果，不能让残句留在历史里被下一轮当成完整回答。
- 流式期间先落 incomplete 标记，落定时摘除；进程中断后靠它区分"未写完"与"已完成"。
- 保存失败不回报保存成功；用本地事实模板汇报已知部分结果，不需要额外模型调用。
- 达到轮次或时限返回 limit_reached，新请求重置预算；时间用尽不叫 context_too_large。
- 硬崩溃后补记中断与可恢复结果，不重放未知副作用。启动收尾把残留的 running/cancel_requested 一次改满三处——runs 状态、`run.finished` 轨迹、以及回答尚未落地时的一条说明消息，三处同一事务。只改状态是不够的：执行日志会停在没有收尾步骤的地方，用户那条消息下面也空无一物，看起来像"悄无声息地断在半路"。若流式期间已落过 incomplete 的助手消息，则只补轨迹、不再加气泡，避免同一次运行出现两条助手消息。
- trace 包含 run、session、步骤、工具、状态、耗时、错误码与脱敏摘要，不保存认证头和密钥。可预期的失败写稳定错误码；未预期异常对外只留异常类型名，堆栈进服务端日志。每个 event_type 在前端都必须有中文文案分支：漏了不会报错，只会在真跑到那条分支时把英文事件名漏到界面上，因此由 `tests/test_trace_contract.py` 静态比对后端埋点与前端分支，替代"新增事件记得补前端"的口头约定。

## 8. 测试和实现顺序

1. 工程骨架、配置、迁移、会话存储与 Fake LLM。
2. 最小 calculator 闭环、真实解析器、参数校验和 trace。
3. 其他工具、会话隔离、持久化、Web 运行和停止。
4. 摘要、预算、外置读取及故障注入。
5. 真实端点联调、双窗口演示、README 与测试报告。

测试随功能实现。T01-T06 覆盖直接回答、组合任务、两类追问；T07-T09 覆盖隔离和重启；T10-T14 覆盖注册、解析、参数、错误和轮次；T15-T18 覆盖压缩/大输入/超时；T19/T23 覆盖事务与幂等；T20 改为单后端双会话并发及同会话忙碌；T21/T22 覆盖 trace 与不可信数据。

新增资源分页无漏读、查找定位、读取不递归外置、比例预算、SSE 重连快照和取消测试。T08 用注入身份验证仓储，不声称有登录认证；不再验证多 CLI 进程锁、PostgreSQL 或逐字流式。

Fake LLM 返回原始协议，测试检查真实工具执行、模型输入和数据库状态，而不只检查预设回复。真实模型烟雾测试单独报告，缺配置为 skipped，不能代替真实自主选择验收。

## 9. 已确认的实施参数

以下参数已由用户选择推荐方案，属于当前实现基线。

### D38 运行预算

已确认 A：总模型请求最多 12 次，包含普通调用、重试和摘要；摘要子上限 2 次、协议纠错最多 2 次；模型超时 60 秒、工具 15 秒、run 180 秒；退避 0.5/1 秒并受剩余时间限制。给多步骤读取留出空间，慢模型仍可能需要调参。

均可配置；最后一次普通生成禁用工具并要求按事实结束，不额外发起总结请求。计数不能叠乘形成无界调用。

### D39 文本和 JSON 读取

已确认 A：不可变 UTF-8 正文，以 Unicode 字符位置定位，字面子串查找并返回附近片段，长行/大 JSON 能继续读取，JSON 片段明确标为正文；不做结构化字段查询。

A 的 read(resource_id,cursor=0,limit?) 按字符范围读取，search(resource_id,query,cursor=0) 返回匹配位置和继续游标；最终仍按 token 预算裁取，字符数不当成 token 数。不加入正则执行或语义检索。

### D40 工程配套

已确认 A：Python 3.11+、aiosqlite、jsonschema、portalocker（仅防同目录重复启动）、pytest/pytest-asyncio；前端使用本地 React 状态、fetch/EventSource、普通 CSS、lucide-react；Playwright 做浏览器验证。依赖少，需要写少量请求和样式代码。
